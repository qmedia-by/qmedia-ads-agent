# Чистый старт вместо форка direct-mcp-ai-project

Соседний репозиторий `direct-mcp-ai-project` решает ту же задачу для одного провайдера (LidFly) и выглядит очевидным кандидатом на форк. Мы его не форкаем: его корневые инструкции целиком построены вокруг meta-layer одного вендора (`search_tools` / `get_tool_schema` / `call_tool` / `call_write_tool`, Пространства, `workspace_project_id`), а мультиплатформенный агент работает с несовместимыми каталогами — у официального MCP Meta плоский набор из ~29 инструментов, у официального Google Ads — три. Форк заставил бы месяцами выпиливать чужие допущения из документа, который агент читает целиком при каждом запуске.

Переносим адресно одну вещь: генератор `scripts/sync-skills.mjs` и дисциплину «правим только `skills-source/`, клиентские копии генерируются».

## Последствия

Улучшения upstream в `direct-mcp-ai-project` к нам автоматически не приезжают. Скиллы для Яндекс Директ и VK, которыми менеджеры уже довольны, придётся переносить руками — это осознанная цена, а не упущение.
