# Прямые подключения к Провайдерам вместо единого шлюза

Менеджер подключает MCP-серверы Провайдеров по отдельности: наш Google Ads на хостинге агентства, `mcp.facebook.com/ads` от Meta, `lidfly.ru/mcp/v3` для Yandex Direct и VK, позже TikTok. Соседний проект `direct-mcp-ai-project` устроен иначе — там один endpoint с единым meta-layer, и соблазн повторить эту схему сильный.

Мы её не повторяем. Собственный шлюз означал бы, что мы строим LidFly заново: нормализация несовместимых каталогов инструментов, проброс OAuth четырёх провайдеров, версионирование собственного слоя. Хуже того, шлюз ставит нас посредником между агентом и вендором — новые инструменты в хостед-сервере Meta стали бы доступны Менеджерам только после нашего релиза.

Цена решения: при первом запуске Менеджер проходит OAuth три-четыре раза, и у каждого Провайдера остаётся свой словарь инструментов, который агент обязан различать.
