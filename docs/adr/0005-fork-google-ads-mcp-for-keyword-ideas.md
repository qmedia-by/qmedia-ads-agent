# Форкаем google-ads-mcp ради одного инструмента generate_keyword_ideas

Официальный `googleads/google-ads-mcp` отдаёт три инструмента: `search` (GAQL), `get_resource_metadata`, `list_accessible_customers`. Сбор семантики через него невозможен: `KeywordPlanIdeaService.GenerateKeywordIdeas` — отдельный RPC, он не запрашивается через GAQL. При этом сбор семантики — центральный сценарий MVP.

Форкаем официальный сервер в отдельный репозиторий и добавляем ровно один инструмент — `generate_keyword_ideas`. Не `KeywordPlanService`, не `RecommendationService`: минимальная дельта — единственное, что делает форк поддерживаемым. Патч накладываем поверх зафиксированной точки upstream, а не rebase'им поверх main.

Изначально предполагался тег upstream, но Google их не публикует — в репозитории нет ни одного. Поэтому база фиксируется конкретным коммитом; актуальный записан в `FORK.md` форка.

Альтернативы отвергнуты: сторонние MCP (gomarble и аналоги) умеют keyword planner из коробки, но возвращают зависимость от вендора, от которой проект уходит; генерация семантики LLM без данных о спросе даёт списки без цифр, и Менеджеры, привыкшие к Wordstat, это распознают сразу.

## Последствия

Форк — долг на поддержку: каждое обновление Google требует переналожения патча. Инструмент работает только если developer token имеет permissible use «Researching keywords and recommendations» — на уровне Explorer эти сервисы заблокированы, и никакой код это не обходит. Для нашего токена (уровень Standard) доступ к `KeywordPlanIdeaService` проверен прямым вызовом REST API и подтверждён.

Отдельный источник работы — версионирование самого Google Ads API: мажорная версия живёт около года, после чего запросы к ней блокируются с `UNSUPPORTED_VERSION`. Значит форк требует внимания по двум независимым осям — за релизами upstream и за сроками жизни версии API — и обновление версии нельзя откладывать до момента, когда сбор семантики встанет у всего отдела разом.
