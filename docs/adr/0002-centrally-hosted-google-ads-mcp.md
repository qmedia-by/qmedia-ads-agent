# Google Ads MCP хостим централизованно на собственной инфраструктуре

Официальный `googleads/google-ads-mcp` документирован как локальный запуск через `pipx` поверх stdio, и это самый простой путь. Мы его не используем: локальный запуск требует, чтобы у каждого Менеджера на машине лежали `GOOGLE_ADS_DEVELOPER_TOKEN` и OAuth client secret — ровно та конфигурация через переменные окружения, которой проект обязан избежать.

Вместо этого разворачиваем один экземпляр в режиме streamable-http с FastMCP OAuth-прокси. Секреты остаются на сервере; Менеджер получает только URL в конфиге репозитория и проходит браузерный OAuth.

Хостим на собственном облачном хостинге с Docker, а не в Google Cloud Run, как планировалось изначально. Причина не техническая: агентство не может провести платёж Google, поэтому billing account для Cloud Run недоступен. На саму интеграцию это не влияет — OAuth-клиент в GCP выдаётся бесплатно и billing не требует, а вызовы Google Ads API через Google Cloud не тарифицируются. Платить нужно только за место, где крутится контейнер, и приложению безразлично, чьё оно.

## Последствия

У проекта появляется собственный инфраструктурный компонент с дежурством, деплоем и мониторингом — в `direct-mcp-ai-project` его не было, потому что там всё хостил вендор. Нужен домен с TLS: он же избавляет от перенастройки `GOOGLE_ADS_MCP_BASE_URL` и Authorized redirect URI при смене адреса. Рядом требуется Redis — с дефолтным хранилищем FastMCP сессии Менеджеров не переживают перезапуск контейнера.
