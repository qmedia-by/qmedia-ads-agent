# Cursor поддерживаем через `.agents/skills`, своего каталога не заводим

Cursor читает скиллы из `.agents/skills/` наравне со своим `.cursor/skills/`, а корневой `AGENTS.md` — как есть. Каталог `.agents/skills` мы уже генерируем для Codex, поэтому третьей копии тех же файлов не появилось: из всей поддержки Cursor понадобился только `.cursor/mcp.json` — схема MCP-конфига у Cursor своя, и `.mcp.json` с `.codex/config.toml` он не читает.

`.cursor/rules/*.mdc` не заводим. Они умеют то, чего не умеет `AGENTS.md`, — привязывать правило к `globs`, — но наши инварианты привязаны к Провайдерам, а не к файлам. Второй корневой источник рядом с `AGENTS.md` разойдётся с ним при первой же правке; ровно поэтому `CLAUDE.md` сделан симлинком ([ADR-0010](./0010-thin-root-instructions.md)).

## Consequences

Поддержка Cursor держится на чужой гарантии. Если Cursor перестанет читать `.agents/skills`, `npm test` останется зелёным, а скиллы в Cursor молча исчезнут — в репозитории нет ничего, что это заметит. Признак: Cursor не предлагает ни одного скилла из репозитория, при том что Codex их видит. Лечится добавлением `.cursor/skills` третьим таргетом в `scripts/sync-skills.mjs` — минута работы, поэтому решение и принято в эту сторону.

Cursor подхватывает `.claude/skills` как legacy-путь, так что наши скиллы попадают к нему двумя дорогами сразу. На версии 3.15.6 проверено вручную: дублей в списке нет.
