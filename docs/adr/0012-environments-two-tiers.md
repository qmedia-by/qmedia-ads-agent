# Сред восемь, уровня поддержки два

Менеджеры приходят с разными Средами, и требовать поставить четвёртую программу ради нашего инструмента — плохая сделка. Поэтому конфиг MCP заводим для всех Сред, до которых дотягиваемся: Claude Code, Codex, Cursor, Gemini CLI, OpenClaw, VS Code, Windsurf, Cline. Файл на Среду стоит десять строк и не требует поддержки — схемы у них разные (`mcpServers` против `servers`, `url` против `serverUrl` и `httpUrl`), но адреса одни, и за этим следит `check-mcp-configs.mjs`.

Скиллы — другое дело. VS Code, Windsurf и Cline формат SKILL.md не читают, и заводить им каталог бессмысленно. Значит, поддержка неоднородна, и делать вид, что она одинаковая, нельзя: **скиллы несут правила безопасной записи** — порядок «прочитал → показал план → получил подтверждение → `call_write_tool`», разбор `goal_mode` у VK, запрет на легаси-путь в Директе. Менеджер, севший в Cline, получает те же write-инструменты LidFly, но без инструкций, как ими пользоваться.

Отсюда два уровня, названные явно в README и в инструкции для Менеджера:

- **полная** — MCP + скиллы + корневые инструкции: Claude Code, Codex, Cursor, Gemini CLI, OpenClaw;
- **ограниченная** — только MCP: VS Code, Windsurf, Cline.

Каталогов скиллов при этом три, а не пять: `.agents/skills` читают Codex, Cursor и OpenClaw, `.claude/skills` — Claude Code, `.gemini/skills` — Gemini CLI. Свой каталог заводится там и только там, где Среда чужие не читает; та же логика, что в [ADR-0011](./0011-cursor-through-agents-skills.md), просто применённая к пяти Средам вместо трёх.

У Gemini CLI одна особенность, которую легко пропустить: по умолчанию он читает `GEMINI.md`, а не `AGENTS.md`. Второго корневого файла мы не заводим ([ADR-0010](./0010-thin-root-instructions.md)) — вместо этого в `.gemini/settings.json` лежит `context.fileName`. Без этой строки Gemini подключился бы к обоим серверам и работал бы вообще без инвариантов, ничем это не обозначив.

## Модель — не Среда

DeepSeek, GPT, Gemini, Claude — это Модели. Своего каталога конфигов и своего формата скиллов у Модели нет: она запускается внутри Среды, и «поддержать DeepSeek» означает поддержать OpenClaw, Cline или VS Code, в которых он работает. Термин заведён в [CONTEXT.md](../../CONTEXT.md), чтобы запрос «добавьте DeepSeek» не превращался в попытку создать `.deepseek/`.

## Последствия

Безопасность записи в Директ и VK держится на тексте, который в трёх Средах из восьми может не загрузиться. Технически мы это не закрываем и закрыть не можем: write-инструменты живут на стороне LidFly, а не у нас, и отключить их для конкретной Среды нечем. Остаётся честное предупреждение в инструкции для Менеджера и рекомендация вести в таких Средах только чтение.

Признак, что мы промахнулись: Менеджер из ограниченной Среды сообщает о правке, сделанной без показанного плана. Лечится переводом Среды в разряд неподдерживаемых, а не добавлением ещё одного файла с правилами, — потому что файл, который Среда не читает, ничего не исправит.

`.openclaw/openclaw.example.json` назван примером не для красоты: OpenClaw читает конфиг из `~/.openclaw/openclaw.json`, а не из проекта, — файл в репозитории только для копирования. Скиллы OpenClaw при этом подхватывает из проекта сам, через `.agents/skills`.
