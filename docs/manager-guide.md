# Инструкция для Менеджера

Агент — помощник по контекстной рекламе, который работает с рекламными кабинетами напрямую: собирает семантику, строит отчёты, создаёт и правит кампании. Вы ставите задачу обычным текстом по-русски, агент делает работу и отдаёт результат файлом.

Инструкцию имеет смысл один раз прочитать сверху вниз, а потом возвращаться к разделам [«Типовые задачи»](#типовые-задачи) и [«Когда что-то не работает»](#когда-что-то-не-работает).

## Что агент умеет, а что нет

| Провайдер | Что доступно |
|---|---|
| Google Ads | **только чтение**: отчёты, аудит, сбор семантики |
| Яндекс Директ | чтение и **изменение**: кампании, группы, ключи, объявления, ставки, бюджеты |
| VK Реклама | чтение и **изменение**: кампании, группы, объявления, лид-формы, аудитории |

Meta и TikTok не подключены. Просить по ним данные бесполезно — агент скажет, что Провайдера нет, и это правда, а не сбой.

**В Google Ads агент ничего не меняет.** Ни ставки, ни бюджеты, ни статусы, ни объявления — инструментов записи там нет вообще. Если правка нужна, её придётся сделать руками в интерфейсе Google Ads. Агент об этом скажет прямо; если вдруг пообещает «сейчас поменяю» — он ошибается, поправьте его.

## Первый запуск

Проходится один раз. Дальше вы просто открываете проект и работаете.

### Шаг 1. Установите Среду

Среда — программа, в которой запускается агент. Их восемь, но возможности у них **не одинаковые**, и это первое, что нужно решить.

**Полная поддержка.** Берите одну из этих, если можете:

- **Claude Code**
- **Codex**
- **Cursor**
- **Gemini CLI**
- **OpenClaw**

Здесь агент получает всё: подключение к кабинетам, инструкции отдела и скиллы — правила, по которым он собирает семантику, строит кампании и не трогает лишнего.

**Ограниченная поддержка.** Подключение к кабинетам работает, скиллы — нет:

- **VS Code** (Copilot и другие расширения с MCP)
- **Windsurf**
- **Cline**

Эти Среды не умеют читать формат, в котором написаны скиллы. Кабинеты агент увидит, отчёт построит, но правила безопасной правки кампаний — порядок «покажи план, дождись подтверждения» — до него не дойдут. **Ничего не меняйте в кабинетах из этих Сред**: читайте, выгружайте, считайте, а правки делайте из Среды с полной поддержкой или руками. Если выбора нет, каждый раз пишите в задаче «ничего не меняй» — и всё равно проверяйте, что агент ничего не поменял.

#### Среда и Модель — не одно и то же

Часто спрашивают про **DeepSeek**. DeepSeek — это Модель, то есть нейросеть, которая думает; Среда — программа, в которой она работает. Отдельно «поставить DeepSeek» нельзя, как нельзя поставить двигатель без машины. Выбирается он внутри Среды, которая это позволяет: OpenClaw, Cline, VS Code. То же самое с Gemini, GPT и Claude.

Инструмент к выбору Модели равнодушен — он даёт агенту инструкции, а не мозги. Но имейте в виду: чем слабее Модель, тем хуже она следует правилам. Требование показать план перед правкой — это текст инструкции, а не кнопка, и модель послабее может его проигнорировать. Для задач с записью в кабинеты берите модель посильнее.

Понадобится ещё **git** — им вы скачаете инструмент и будете его обновлять.

### Шаг 2. Склонируйте репозиторий

Откройте терминал, перейдите туда, где хотите держать папку с инструментом, и выполните:

```bash
git clone https://github.com/qmedia-by/qmedia-ads-agent.git
```

Появится папка `qmedia-ads-agent` — это и есть инструмент.

Актуальная версия живёт в ветке **`dev`**, и она же ветка по умолчанию: после обычного клонирования вы окажетесь именно на ней, переключаться никуда не нужно. Убедиться можно так:

```bash
git branch --show-current
```

Ответ должен быть `dev`. Если там что-то другое — вернитесь на `dev`:

```bash
git checkout dev
```

Устанавливать больше нечего: внутри только инструкции и текст, никаких зависимостей и сборки.

### Шаг 3. Откройте папку как проект

Запустите Среду и откройте в ней папку `qmedia-ads-agent` — именно как проект, а не отдельный файл.

Шаг важнее, чем кажется: агент читает инструкции и правила работы с Клиентами из этой папки. Запущенный где-то ещё, он не будет знать ни про Провайдеров, ни про ваших Клиентов, и начнёт выдумывать.

### Шаг 4. Попросите добавить вас в Test users

Наше OAuth-приложение Google работает в статусе Testing, и войти в него могут только заранее добавленные аккаунты. Пока вас не добавили, авторизация в Google Ads не пройдёт — никакие настройки этого не обойдут.

Напишите тому, кто администрирует MCP-сервер, и назовите рабочий Google-аккаунт — тот самый, под которым у вас есть доступ к кабинетам Клиентов.

### Шаг 5. Пройдите OAuth в обоих серверах

Серверов два, и авторизоваться нужно в каждом: `google-ads` и `lidfly`.

| Среда | Где авторизоваться |
|---|---|
| Claude Code | команда `/mcp` |
| Codex | `codex mcp login google-ads`, затем `codex mcp login lidfly` |
| Cursor | страница **Customize** в боковой панели, там же список MCP-серверов |
| Gemini CLI | при первом обращении к серверу Gemini сам предложит войти |
| OpenClaw | сначала скопируйте конфиг (ниже), затем войдите по приглашению в сессии |
| VS Code | кнопка **Authenticate** или **Connect** у сервера в панели MCP |
| Windsurf | перезапустите Windsurf, кнопка подключения появится в Cascade |
| Cline | кнопка входа у сервера в списке MCP-серверов |

**Только для OpenClaw** — один разовый шаг перед входом. OpenClaw читает настройки не из папки проекта, а из своей, поэтому конфиг нужно скопировать. Выполните в папке `qmedia-ads-agent`:

```bash
mkdir -p ~/.openclaw && cp .openclaw/openclaw.example.json ~/.openclaw/openclaw.json
```

Если файл `~/.openclaw/openclaw.json` у вас уже есть и вы им пользуетесь — не затирайте его, а перенесите в него два сервера из примера руками.

На экране входа Google покажет предупреждение «Google hasn't verified this app». Это ожидаемо: приложение наше, внутреннее, и проверку Google оно не проходит намеренно. Раскройте **Advanced** и продолжите.

### Шаг 6. Проверьте, что всё живо

```text
Проверь подключение к Google Ads и LidFly.
```

Агент назовёт, какая Среда у вас определилась и какие серверы отвечают. Если что-то не так — он скажет ровно одно следующее действие; сделайте его и повторите проверку.

Дальше попробуйте настоящий запрос:

```text
Покажи кампании клиента <название> в Google Ads за последние 30 дней.
```

## Обновление инструмента

Инструмент меняется: появляются новые возможности, уточняются правила, добавляются Провайдеры. У вас на компьютере лежит копия, снятая в день клонирования, и сама она не обновляется.

Обновление — одна команда, выполненная **в папке `qmedia-ads-agent`**:

```bash
git pull
```

Актуальная версия — всегда ветка `dev`, а `git pull` тянет обновления в ту ветку, на которой вы стоите. Если не уверены, где вы:

```bash
git branch --show-current
```

Ответ не `dev` — вернитесь на неё и повторите `git pull`:

```bash
git checkout dev
```

**После обновления перезапустите сессию агента.** Инструкции и скиллы читаются один раз, при старте: пока открыта старая сессия, агент продолжает работать по прежней версии, даже если файлы на диске уже новые.

Когда обновляться:

- когда в отделе сказали, что вышло обновление;
- когда агент ведёт себя не так, как описано в этой инструкции;
- просто время от времени — это быстро и ничего не ломает.

Не уверены, отстала ли ваша копия, — спросите агента:

```text
Проверь подключение.
```

Он проверит в том числе и это: скажет, на сколько версий вы отстали, и предложит обновиться. Сам `git pull` он не делает намеренно — обновление это ваше решение, и подействует оно всё равно только в новой сессии.

### Если `git pull` ругается

Чаще всего он жалуется на локальные изменения — значит, в папке что-то случайно поправили или файл изменила сама Среда. Менеджеру править в репозитории нечего, поэтому проще всего откатить и повторить:

```bash
git checkout .
```

```bash
git pull
```

Если и это не помогло — удалите папку и склонируйте репозиторий заново (Шаг 2). Ничего вашего в ней не хранится: результаты работы агент отдаёт файлами, а Реестр Клиентов лежит вообще не здесь. Потерять нечего.

## Как ставить задачу

Три привычки, которые экономят больше всего времени.

**1. Агент не помнит ничего между сессиями.** Каждый новый разговор начинается с чистого листа: он не знает, что вы делали вчера, какой у Клиента регион и какие KPI. Всё, что важно, называйте заново.

**2. Называйте Клиента по имени.** Связка Клиента с его кабинетами лежит в Реестре — закрытой таблице агентства. Доступ к таблице вам не нужен: её читает наш сервер, агенту достаточно имени. Пишите его как привыкли — регистр, пробелы и знаки препинания при поиске не важны, узнаваемой части названия хватит.

Идентификаторы кабинетов диктовать не нужно, и лучше не надо: агент обязан взять их из Реестра, а не с ваших слов. Единственное исключение — если Реестр не читается; тогда он сам попросит назвать `customer_id`.

**3. Регион и язык — всегда явно.** Особенно для семантики. Ошибка здесь не выглядит как ошибка: вы получите красивую таблицу с правдоподобными числами по чужой стране, и ничто в ней на это не укажет. Агент обязан переспросить, если вы не назвали, но проще сказать сразу.

Плохо:

```text
Собери ключи по окнам.
```

Хорошо:

```text
Собери семантику для клиента <название>: услуга — установка пластиковых окон,
регион — Беларусь, язык русский, посадочная — https://example.by/okna.
```

Если у Клиента несколько Аккаунтов у одного Провайдера — агент спросит, какой брать. Это обычное дело: кабинеты разведены по странам и направлениям. Не отвечайте «любой» и не просите «посчитай по всем» — цифры из разных кабинетов нельзя складывать, суммы не окажется ни в одном отчёте.

Идентификатор Google Ads можно называть как удобно: агент понимает и `1234567890`, и `123-456-7890`, как показывает интерфейс.

## Типовые задачи

Формулировки ниже можно копировать и подставлять своё.

### Собрать семантику

```text
Собери семантику для клиента <название>: услуга — <услуга>,
регион — <страна или регион>, язык <язык>, посадочная — <url>.
```

Частотность и конкуренцию агент берёт из Google Ads. Посадочную страницу называйте, если она есть: по странице охват получается заметно шире, чем по одним ключевым словам.

Результат — CSV: фраза, частотность, конкуренция, вилка ставок. Колонки под группировку остаются пустыми — их заполняет следующая задача.

### Сгруппировать собранное

```text
Сгруппируй эти запросы по интенту и предложи посадочные страницы.
Кластеры нужны под <группы объявлений / структуру сайта / контент-план>.
```

Группировка идёт по уже собранным данным, без обращений к Провайдеру. Поэтому её можно переделывать сколько угодно раз — квота не тратится, и просить «а теперь разбей иначе» совершенно нормально.

Скажите, подо что кластеры: под группы объявлений, под структуру сайта и под контент-план одно и то же ядро разбивается по-разному.

Минус-слова агент отдаёт отдельным списком, а не подмешивает в таблицу фраз.

### Отчёт по кампаниям

```text
Покажи статистику по кампаниям клиента <название> в <Провайдер>
за <период>. Отдай файлом.
```

Всегда называйте период. Запрос без границ по датам на большом Аккаунте возвращает намного больше, чем нужно, и тормозит работу.

В ответе проверьте три вещи: имя Клиента словами, идентификатор Аккаунта цифрами и валюту. Валюта принадлежит Аккаунту и не обязана совпадать с той, в которой вы считаете.

### Аудит кампании, ничего не меняя

```text
Проверь кампанию «<название>» у клиента <название> в Директе, ничего не меняй.
```

Оговорка «ничего не меняй» не обязательна — без подтверждения агент и так не пишет, — но она снимает лишние вопросы и делает задачу однозначной.

### Создать или поправить кампанию

```text
Собери поисковую кампанию в Директе для клиента <название>:
регион <регион>, бюджет <сумма> ₽ в день, посадочная <url>.
Покажи план перед созданием.
```

Работает для Яндекс Директа и VK. Как проходит подтверждение — в следующем разделе.

Бюджеты Директа называйте в рублях. Кампании по умолчанию собираются под поиск: если нужны сети, скажите об этом явно.

### Сохранить контекст проекта

У Яндекс Директа и VK есть память на стороне LidFly — Пространства. Туда складываются решения, слепки кампаний, документы и задачи на будущее.

```text
Сохрани это решение в Пространство проекта <название>.
```

Две вещи, которые легко перепутать:

- **напоминание** — просто письмо вам в назначенный день, никто ничего не запускает;
- **AI-автозапуск** — LidFly сам выполнит сохранённый план в назначенное время, без единого вопроса.

Если планируете автозапуск, вычитайте план целиком: переспросить в момент выполнения будет уже некому.

**У Google Ads Пространств нет.** Что вы сохранили по Директу, при работе с Google Ads того же Клиента недоступно.

## Как проходит изменение

Ни одна правка не уходит в кабинет молча. Порядок всегда один:

1. Агент читает текущее состояние кампании.
2. Показывает план: что именно меняется и как это скажется на бюджете.
3. Ждёт вашего подтверждения текстом.
4. Выполняет и перечитывает результат.
5. Показывает, что было и что стало.

Перед «да» посмотрите на четыре вещи: тот ли Клиент и Аккаунт, какие поля меняются, какие суммы, и не задета ли цель или стратегия. Смену цели, стратегии или бюджета больше чем на 30% агент вынесет в отдельное подтверждение — это тот случай, когда стоит притормозить.

Не отвечайте «делай всё» на план, который не прочитали. Подтверждение — единственное место, где ошибку ещё дёшево остановить.

## Результаты

Табличные данные агент отдаёт файлом CSV, который вы сами импортируете в таблицу. Рядом с числами он обязан назвать период, Аккаунт и валюту — без этого через неделю отчёт нельзя будет прочитать.

За чем стоит следить в ответах:

- **Оценка помечена как оценка.** Если цифра получена расчётом, а не прочитана у Провайдера, это должно быть написано.
- **Пустая ячейка — не ноль.** Отсутствие данных и нулевая частотность это разные факты, и агент не заполняет первое вторым.
- **Идентификатор Аккаунта на месте.** Он в ответе именно для того, чтобы вы могли проверить, что смотрели в нужный кабинет.

Если агент чего-то не смог — он скажет об этом прямо. Правдоподобные числа вместо ошибки — поведение, которого быть не должно; если заметили, сообщите тому, кто ведёт репозиторий.

## Когда что-то не работает

### Google Ads отвалился примерно через неделю

Это ожидаемо. Токены Google Ads живут 7 дней и затем протухают — свойство статуса Testing, а не поломка. Признак: раньше в этой же сессии всё работало, а теперь Google Ads отвечает ошибкой авторизации. LidFly при этом продолжает работать, у него своя авторизация.

Что делать: пройдите OAuth сервера `google-ads` заново (Шаг 5) и повторите запрос.

Если доступ пропал разом у нескольких Менеджеров, а не у вас одного, — дело не в семи днях, а в перезапуске сервера. Скажите администратору.

### Любая другая ошибка

```text
Проверь подключение.
```

Агент сам разберётся, на каком слое сбой — настройка Среды, авторизация, доступ к Аккаунту, связь или устаревшая копия инструмента, — и назовёт одно следующее действие. Не нужно ни описывать симптомы, ни лезть в конфиги: делайте то, что он скажет, а если не помогло — скажите, что не помогло.

### «Клиента нет в Реестре»

Значит, строки для него в таблице ещё нет. Агент в Реестр не пишет и подбирать кабинет по похожему названию не станет — именно так отчёт и уезжает не тому Клиенту.

Иногда это не ошибка, а верный ответ: у части Клиентов агентства нет ни Google Ads, ни VK — они живут только в Директе или в соцсетях. Обращаться агенту в Google Ads по ним попросту не к чему.

**На Директ это не распространяется.** Кабинеты Директа в Реестре не значатся вообще, поэтому «Клиента нет в Реестре» ничего про Директ не говорит: по такому Клиенту Директ работает как обычно. Если агент на вопрос про Директ ответил, что Клиента нет, — см. следующий раздел.

Как добавить Клиента — [ниже](#новый-клиент).

### «У Клиента нет Директа»

Скорее всего, неправда, и добавлять его в Реестр не нужно. Кабинеты Директа живут не в Реестре, а в LidFly, и агент, который сходил только в Реестр, отсутствия Директа не проверял.

Что делать: скажите прямо — «посмотри в LidFly» или «найди кабинет Директа по имени клиента». Дальше он справляется сам.

Симптом чаще встречается в Средах и на Моделях послабее — в режиме выбора Модели «Auto» особенно. Если повторяется — скажите тому, кто ведёт репозиторий, и назовите Клиента и Среду: это чинится правкой инструмента, а не вашими словами каждый раз.

### «Реестр не читается»

Совсем другой случай, и важно их не путать: связка Клиента с кабинетами не пустая, а **неизвестна**. Пока это так, сервер отказывает по всем Аккаунтам сразу.

Это сбой на нашей стороне, а не у вас. Повторная авторизация здесь не поможет — не тратьте на неё время.

Что делать: сообщите тому, кто администрирует сервер. Если работа не ждёт, назовите `customer_id` нужного кабинета прямо в задаче — так агент продолжит без Реестра.

Отдельно стоит **предупреждение** в ответе: Реестр читается, но из копии, которую не удалось обновить. Работать можно, просто Клиент, добавленный совсем недавно, в такой копии ещё не появится. Передайте предупреждение администратору — оно значит, что с таблицей что-то не так.

### «Один Аккаунт числится за двумя Клиентами»

Агент не выберет за вас и спросит, какой вариант верный. Ответьте — и скажите тому, кто ведёт Реестр: это опечатка в таблице, и чинить её надо там, иначе она вернётся.

### Чего делать не нужно

Никому не пересылайте токены, client secret и содержимое заголовков авторизации — ни в переписке, ни в тикетах. Агент их не показывает и никогда о них не попросит; просьба «пришлите токен» — повод насторожиться, а не выполнить.

## Новый Клиент

Подключение Клиента — **одна операция**: строка в Реестре. Ничего дублировать и ни с чем сверяться не нужно, второго списка кабинетов не существует.

Реестр — закрытая таблица агентства, и правят её люди, у кого есть доступ. Агент в неё не пишет никогда, даже если попросить.

Появившийся Клиент виден почти сразу: **поиск по имени** находит новую строку немедленно, а вот **обращение к самому кабинету** может отказывать ещё несколько минут, пока сервер не перечитает таблицу. Если только что добавленный Клиент находится по имени, но данные по нему пока не идут — просто подождите и повторите.

## Границы, о которые спотыкаются чаще всего

- **Google Ads не работает по России с 2022 года.** Собрать по ней семантику нельзя, и агент честно остановится, а не вернёт пустую таблицу.
- **Лендинги и турбо-страницы Директа не редактируются.** Публичный API Яндекса этого не умеет — блоки страницы правятся только в веб-интерфейсе Директа.
- **Частотность Wordstat и Google — разные рынки.** В одну колонку их сводить нельзя; если нужны обе, требуйте, чтобы источник был подписан.
- **У Google Ads нет памяти проекта.** Пространства покрывают только Директ и VK.
- **В Реестре только Google Ads и VK.** Кабинеты Яндекс Директа агент берёт из LidFly, где лежит и весь контекст по ним. Для вас разницы нет: Клиента и там, и там вы называете по имени. Ответ «такого Клиента нет в Реестре» — про Google Ads и VK, а не про Директ.
- **Репозиторий агент не правит.** Отчёты, заметки и кэш он туда не складывает — результат приходит файлом вам.
- **В VS Code, Windsurf и Cline скиллов нет.** Это не поломка и не лечится обновлением: сами эти программы такой формат не читают. Оттуда — только чтение ([Шаг 1](#шаг-1-установите-среду)).
