# Инструкция для Менеджера

Агент собирает семантику, строит отчёты, создаёт и правит кампании в рекламных кабинетах. Задачу ставите обычным текстом по-русски, результат получаете файлом.

| Провайдер | Доступ |
|---|---|
| Google Ads | **только чтение**: отчёты, аудит, семантика |
| Яндекс Директ | чтение и запись |
| VK Реклама | чтение и запись |

Meta и TikTok не подключены. В Google Ads агент ничего не меняет — правки только руками в интерфейсе.

## Что установить

**1. [Git](https://git-scm.com/install/)** — им скачивается и обновляется инструмент.

**2. Среда** — программа, в которой запускается агент: Claude Code, Codex, Cursor, Gemini CLI, OpenClaw, VS Code, Windsurf, Cline.

**3. Репозиторий:**

Открыть в нужно папке на компьютере терминал и вызвать команду

```bash
git clone https://github.com/qmedia-by/qmedia-ads-agent.git
```

---

## Как запустить

**1.** Откройте созданную Git папку `qmedia-ads-agent` в Среде — **как проект**, не отдельным файлом. Запущенный в другом месте агент не увидит ни инструкций, ни ваших Клиентов.

**2.** Проверьте связь. Введите в чат агента:

```text
Проверь подключение
```

Агент назовёт, что отвечает, а что нет, и даст одно следующее действие.

## Авторизация MCP

**Сначала** попросите администратора MCP-сервера (Игорь Спургяш) добавить ваш рабочий Google-аккаунт в Test users. Пока не добавили — Google Ads не авторизуется, никакие настройки этого не обойдут.

Авторизоваться нужно **в двух серверах**: `google-ads` и `lidfly`.

| Среда | Где |
|---|---|
| Claude Code | команда `/mcp` |
| Codex | `codex mcp login google-ads`, затем `codex mcp login lidfly` |
| Cursor | боковая панель → **Customize** → список MCP-серверов |
| Gemini CLI | предложит войти сам при первом обращении |
| OpenClaw | скопируйте конфиг (ниже), затем войдите по приглашению |
| VS Code | кнопка **Authenticate** / **Connect** у сервера в панели MCP |
| Windsurf | перезапустите Windsurf, кнопка появится в Cascade |
| Cline | кнопка входа у сервера в списке MCP |

> **Только для OpenClaw** — разовый шаг перед входом, выполнить в папке проекта:
> ```bash
> mkdir -p ~/.openclaw && cp .openclaw/openclaw.example.json ~/.openclaw/openclaw.json
> ```
>
> Если свой `~/.openclaw/openclaw.json` уже есть — не затирайте, перенесите два сервера руками.
>
> Предупреждение Google «hasn't verified this app» — ожидаемо. **Advanced** → продолжить.

## Обновление

В терминале из папки `qmedia-ads-agent`:

```bash
git pull
```

**После обновления перезапустите сессию агента** — инструкции читаются только при старте.

Обновляйтесь либо после просьбы от разработчика, либо когда агент ведёт себя не как в инструкции, или просто время от времени.

Если `git pull` ругается на локальные изменения:

```bash
git checkout .
```

и повторите `git pull`. Не помогло — удалите папку и склонируйте заново: ничего вашего в ней не хранится.

## Типовые задачи

Общие правила: **агент не помнит ничего между сессиями**; Клиента называйте по имени (идентификаторы кабинетов диктовать не надо); регион, язык и период — всегда явно.

### Семантика

```text
Собери семантику для клиента <название>: услуга — <услуга>,
регион — <страна>, язык <язык>, посадочная — <url>.
```

Результат — CSV: фраза, частотность, конкуренция, вилка ставок.

### Группировка

```text
Сгруппируй эти запросы по интенту и предложи посадочные.
Кластеры нужны под <группы объявлений / структуру сайта / контент-план>.
```

Идёт по уже собранным данным — переделывать можно сколько угодно.

### Отчёт

```text
Покажи статистику по кампаниям клиента <название> в <Провайдер>
за <период>. Отдай файлом.
```

Период обязателен. В ответе проверьте: имя Клиента, идентификатор Аккаунта, валюту.

### Аудит

```text
Проверь кампанию «<название>» у клиента <название> в Директе, ничего не меняй.
```

### Создать или поправить кампанию

```text
Собери поисковую кампанию в Директе для клиента <название>:
регион <регион>, бюджет <сумма> ₽ в день, посадочная <url>.
Покажи план перед созданием.
```

Директ и VK. Агент показывает план и ждёт подтверждения текстом — **прочитайте его перед «да»**: тот ли Клиент и Аккаунт, какие суммы, не задета ли цель или стратегия.

### Сохранить контекст проекта

```text
Сохрани это решение в Пространство проекта <название>.
```

Директ и VK, у Google Ads такой памяти нет. Не путайте **напоминание** (письмо вам) и **AI-автозапуск** (LidFly сам выполнит план в назначенное время, без вопросов).

## Типовые ошибки

| Симптом | Что это | Что делать |
|---|---|---|
| Google Ads отвалился примерно через неделю | токен живёт 7 дней, это норма | пройдите OAuth `google-ads` заново |
| Любая другая ошибка | — | напишите `Проверь подключение.` и сделайте, что скажет |
| «Клиента нет в Реестре» | строки в таблице нет | скажите тому, кто ведёт Реестр. Про Директ это ничего не значит — см. ниже |
| «У Клиента нет Директа» | скорее всего неправда | скажите «посмотри в LidFly» или «найди кабинет Директа по имени клиента» |
| «Реестр не читается» | сбой на нашей стороне | сообщите администратору. Срочно — назовите `customer_id` прямо в задаче |
| «Аккаунт числится за двумя Клиентами» | опечатка в таблице | ответьте агенту, какой верный, и скажите тому, кто ведёт Реестр |
| Просят прислать токен или client secret | так не бывает | не присылайте. Агент их не показывает и не просит |

Отдельно: если агент выдал правдоподобные числа вместо честной ошибки — сообщите тому, кто ведёт репозиторий.

### Что агент не может в принципе

- Google Ads не работает по России с 2022 года.
- Лендинги и турбо-страницы Директа не редактируются (ограничение API Яндекса).
- Частотность Wordstat и Google в одну колонку не сводится.
- Новый Клиент подключается одной строкой в Реестре; агент в Реестр не пишет никогда.
