# qmedia-ads-agent

Инструкции и скиллы для AI-агента, работающего с рекламными кампаниями в Google Ads, Яндекс Директе и VK. Агент запускается в любой из восьми Сред — от Claude Code до Cline; репозиторий он использует только на чтение.

Секретов здесь нет и быть не должно. Никаких `.env`, никаких токенов: авторизация у всех Провайдеров идёт через браузерный OAuth, а developer token и client secret Google Ads живут на сервере агентства.

## Что подключено

| Провайдер | MCP | Доступ |
|---|---|---|
| Google Ads | собственный сервер агентства | только чтение |
| Yandex Direct | `https://lidfly.ru/mcp/v3` | чтение и запись |
| VK | `https://lidfly.ru/mcp/v3` | чтение и запись |

Meta и TikTok — после MVP. У обеих площадок есть официальные MCP-серверы, но Meta пока в open beta с поаккаунтной раскаткой.

## Среды

Среда — программа, в которой запускается агент. Уровня поддержки два, и разница между ними существенная: скиллы несут правила безопасной записи, и там, где их нет, агент работает на одних корневых инструкциях.

| Среда | Конфиг MCP | Скиллы | Инструкции |
|---|---|---|---|
| Claude Code | `.mcp.json` | `.claude/skills` | `CLAUDE.md` → `AGENTS.md` |
| Codex | `.codex/config.toml` | `.agents/skills` | `AGENTS.md` |
| Cursor | `.cursor/mcp.json` | `.agents/skills` | `AGENTS.md` |
| Gemini CLI | `.gemini/settings.json` | `.gemini/skills` | `AGENTS.md` через `context.fileName` |
| OpenClaw | `.openclaw/openclaw.example.json` | `.agents/skills` | `AGENTS.md` |
| VS Code | `.vscode/mcp.json` | — | зависит от расширения |
| Windsurf | `.windsurf/mcp.json` | — | зависит от версии |
| Cline | `.cline/mcp_settings.json` | — | зависит от версии |

Нижние три строки — **ограниченная поддержка**: формат SKILL.md они не читают. Подробности и порядок подключения каждой — в [инструкции для Менеджера](docs/manager-guide.md#шаг-1-установите-среду), причины именно такого деления — в [ADR-0012](docs/adr/0012-environments-two-tiers.md).

DeepSeek, GPT, Gemini и Claude — это Модели, а не Среды. Модель Менеджер выбирает сам внутри Среды; отдельной поддержки она не требует и не получает (см. [CONTEXT.md](CONTEXT.md)).

## Быстрый старт для Менеджера

Подробный разбор с типовыми задачами — в [инструкции для Менеджера](docs/manager-guide.md). Ниже — только то, без чего не начать.

1. Клонируйте репозиторий и откройте его как проект в своей Среде. Полная поддержка — Claude Code, Codex, Cursor, Gemini CLI, OpenClaw; VS Code, Windsurf и Cline получают только MCP, без скиллов (см. [Среды](#среды)).
2. Убедитесь, что ваш рабочий Google-аккаунт внесён в Test users — без этого OAuth Google Ads не пройдёт. Если не уверены, спросите у того, кто администрирует MCP-сервер.
3. Пройдите OAuth для обоих серверов, `google-ads` и `lidfly`. Где это делается для каждой Среды — [в инструкции для Менеджера](docs/manager-guide.md#шаг-5-пройдите-oauth-в-обоих-серверах).
4. Проверьте, что всё живо:

```text
Покажи кампании клиента <название> в Google Ads за последние 30 дней.
```

**OAuth Google Ads протухает каждые 7 дней** — это известное свойство, а не поломка (см. [ADR-0007](docs/adr/0007-oauth-app-stays-in-testing.md)). При ошибке авторизации просто пройдите вход заново; агент подскажет это сам через скилл `connection-doctor`.

## Что умеет

```text
Собери семантику для <услуга> по Беларуси, язык русский.
```

```text
Сгруппируй эти запросы по интенту и предложи посадочные страницы.
```

```text
Проверь кампанию «Бренд» в Директе, ничего не меняй.
```

Результаты агент отдаёт файлом — CSV, который вы импортируете в таблицу. Между сессиями он ничего не помнит, поэтому регион и язык называйте явно.

## Клиенты и Аккаунты

Связка Клиента с его рекламными кабинетами живёт в закрытой таблице агентства — Реестре. В репозитории её нет и не будет: репозиторий публичный, а список клиентов с их идентификаторами в открытом доступе быть не должен ([ADR-0008](docs/adr/0008-account-registry-single-source.md)).

Агент читает Реестр инструментом `registry_find_client` нашего сервера Google Ads; доступа к самой таблице Менеджеру для этого не нужно. Достаточно назвать Клиента по имени:

```text
Покажи кампании клиента <название> в Google Ads за последние 30 дней.
```

Реестр — ещё и allowlist сервера: Аккаунт, которого в таблице нет, сервер не отдаст. Поэтому **подключение Клиента — одна операция**: строка в Реестре. Изменения подхватываются в течение пяти минут, а поиск по имени видит их сразу. Подробнее — в [ADR-0003](docs/adr/0003-google-ads-mcp-access-control.md).

В Реестре только Google Ads и VK. Аккаунты Яндекс Директа агент берёт из LidFly — там же, где живёт их контекст.

## Разработка

Скиллы правятся **только** в `skills-source/`. Копии для Сред генерируются:

```bash
npm run sync
```

Каталогов три, а Сред со скиллами пять: `.agents/skills` читают Codex, Cursor и OpenClaw, `.claude/skills` — Claude Code, `.gemini/skills` — Gemini CLI. Свой каталог заводится только там, где Среда чужие не читает; причины — в [ADR-0011](docs/adr/0011-cursor-through-agents-skills.md) и [ADR-0012](docs/adr/0012-environments-two-tiers.md).

А вот MCP-конфиг у каждой Среды свой, и схемы у них разные — `mcpServers` против `servers`, `url` против `serverUrl` и `httpUrl`. Файлы перечислены в таблице [Среды](#среды) выше.

Проверки перед PR:

```bash
npm test
```

Линт следит за структурой скиллов и синхронностью копий, `test-skill-rules.mjs` — за тем, что критичные правила не выпали из инструкций при переписывании, `check-mcp-configs.mjs` — за тем, что MCP-конфиги всех восьми Сред указывают на одни и те же адреса, описаны в README и не содержат статических ключей вместо OAuth. Проверки Реестра здесь больше нет: он валидируется на сервере в момент чтения, потому что PR-ревью у таблицы нет.

## Инфраструктура

MCP-сервер Google Ads — форк [googleads/google-ads-mcp](https://github.com/googleads/google-ads-mcp) с одним добавленным инструментом `planning_generate_keyword_ideas`, живёт в отдельном репозитории. Официальный сервер собирать семантику не умеет: `KeywordPlanIdeaService` не запрашивается через GAQL.

Разворачивается в Docker на хостинге агентства по адресу `https://google-ads-mcp.qmedia.by/mcp`, рядом нужен Redis — иначе сессии Менеджеров не переживают перезапуск контейнера. Полный список переменных окружения и порядок развёртывания — в `FORK.md` репозитория форка.
