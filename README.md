# qmedia-ads-agent

Инструкции и скиллы для AI-агента, работающего с рекламными кампаниями в Google Ads, Яндекс Директе, VK и Meta. Агент запускается в любой из шести Сред — от Claude Code до VS Code; репозиторий он использует только на чтение.

Секретов здесь нет и быть не должно. Никаких `.env`, никаких токенов: авторизация у всех Провайдеров идёт через браузерный OAuth, а developer token и client secret Google Ads живут на сервере агентства.

## Что подключено

| Провайдер | MCP | Доступ |
|---|---|---|
| Google Ads | собственный сервер агентства | только чтение |
| Yandex Direct | `https://lidfly.ru/mcp/v3` | чтение и запись |
| VK | `https://lidfly.ru/mcp/v3` | чтение и запись |
| Meta | `https://mcp.facebook.com/ads` | чтение и правка существующего |

В Meta агент правит существующие кампании — бюджеты, статусы, ставки, таргетинг — но не создаёт новых. Сервер Meta в open beta с поаккаунтной раскаткой: инструмент, недоступный для одного кабинета при исправном подключении, — это она, а не сбой авторизации.

TikTok — после MVP. Официальный MCP-сервер у него есть; подключение — отдельный проект со своей авторизацией и своим скиллом.

## Среды

Среда — программа, в которой запускается агент. Уровня поддержки два, и разница между ними существенная: скиллы несут правила безопасной записи, и там, где их нет, агент работает на одних корневых инструкциях.

| Среда | Конфиг MCP | Скиллы | Инструкции |
|---|---|---|---|
| Claude Code | `.mcp.json` | `.claude/skills` | `CLAUDE.md` → `AGENTS.md` |
| Codex | `.codex/config.toml` | `.agents/skills` | `AGENTS.md` |
| Cursor | `.cursor/mcp.json` | `.agents/skills` | `AGENTS.md` |
| Gemini CLI | `.gemini/settings.json` | `.gemini/skills` | `AGENTS.md` через `context.fileName` |
| OpenClaw | `.openclaw/openclaw.example.json` | `.agents/skills` | `AGENTS.md` |
| VS Code | `.vscode/mcp.json` | — | зависит от расширения |

Нижняя строка — **ограниченная поддержка**: формат SKILL.md VS Code не читает. Windsurf и Cline поддерживались раньше и сняты: они получали инструменты записи всех Провайдеров без единого правила обращения с ними, а с приходом Meta, где правка бюджета применяется сразу, риск перестал быть приемлемым — [почему именно так](docs/environments.md#windsurf-and-cline-were-dropped). Подробности и порядок подключения каждой — в [docs/environments.md](docs/environments.md), причины именно такого деления — в [docs/environments.md](docs/environments.md).

Строка VS Code, скорее всего, устарела: сегодняшний VS Code читает скиллы из `.agents/skills` и `.claude/skills`, а `AGENTS.md` — при включённом `chat.useAgentsMdFile`. Пока это не проверено на живой версии, обещание Менеджерам мы не меняем — [почему](docs/environments.md#open-question-vs-code-is-under-served).

DeepSeek, GPT, Gemini и Claude — это Модели, а не Среды. Модель Менеджер выбирает сам внутри Среды; отдельной поддержки она не требует и не получает (см. [CONTEXT.md](CONTEXT.md)).

## Быстрый старт для Менеджера

Менеджерам предъявляется **одна** Среда — VS Code с расширением Codex. Шесть конфигов ниже существуют для разработки; выбирать из них Менеджер не должен и не выбирает ([почему](docs/environments.md#one-environment-is-offered-to-managers)).

Пошаговая настройка — в [инструкции по настройке](docs/manager-setup.md), задачи и разбор ошибок — в [инструкции для Менеджера](docs/manager-guide.md). Ниже — только то, без чего не начать.

1. Установите VS Code, Git и расширение ChatGPT – Codex, склонируйте репозиторий и откройте папку как проект.
2. Убедитесь, что ваш рабочий Google-аккаунт внесён в Test users — без этого OAuth Google Ads не пройдёт. Если не уверены, спросите у того, кто администрирует MCP-сервер.
3. Пройдите OAuth для всех трёх серверов: `google-ads`, `lidfly` и `meta` — в Codex это экран **Configure MCP servers**.
4. Проверьте, что всё живо:

```text
Покажи кампании клиента <название> в Google Ads за последние 30 дней.
```

**OAuth Google Ads протухает каждые 7 дней** — это известное свойство, а не поломка (почему так — в [docs/providers.md](docs/providers.md#google-ads)). При ошибке авторизации просто пройдите вход заново; агент подскажет это сам через скилл `connection-doctor`.

## Что умеет

```text
Собери семантику для <услуга> по Беларуси, язык русский.
```

```text
Сгруппируй эти запросы по интенту и предложи посадочные страницы.
```

```text
Проверь кампанию «Бренд» в Директе, ничего не меняй.
```

Результаты агент отдаёт файлом — CSV, который вы импортируете в таблицу. Между сессиями он ничего не помнит, поэтому регион и язык называйте явно.

## Клиенты и Аккаунты

Связка Клиента с его рекламными кабинетами живёт в закрытой таблице агентства — Реестре. В репозитории её нет и не будет: репозиторий публичный, а список клиентов с их идентификаторами в открытом доступе быть не должен ([docs/architecture.md](docs/architecture.md#the-registry)).

Агент читает Реестр инструментом `registry_find_client` нашего сервера Google Ads; доступа к самой таблице Менеджеру для этого не нужно. Достаточно назвать Клиента по имени:

```text
Покажи кампании клиента <название> в Google Ads за последние 30 дней.
```

Реестр — ещё и allowlist сервера **для Google Ads**: Аккаунт Google Ads, которого в таблице нет, сервер не отдаст. Поэтому **подключение Клиента — одна операция**: строка в Реестре. Изменения подхватываются в течение пяти минут, а поиск по имени видит их сразу. Подробнее — в [docs/invariants.md](docs/invariants.md#access-control-has-two-layers-and-both-fail-closed).

Для остальных Провайдеров Реестр — только навигация: их кабинеты живут на чужих серверах, и запретить там что-либо он не может. Отсутствие строки по Meta или Директу — не отказ и не доказательство, что кабинета нет ([почему это важно](docs/invariants.md#the-registry-is-a-boundary-for-google-ads-and-navigation-for-everyone-else)).

В Реестре Google Ads, VK, Meta и логины Яндекс Директа — последние там, где в таблице логин записан отдельно от пароля. Сам кабинет Директа и контекст по нему агент всё равно разрешает в LidFly, а кабинет Meta при пустой строке ищет в самом Meta и спрашивает Менеджера, какой из них нужен.

## Разработка

Скиллы правятся **только** в `skills-source/`. Копии для Сред генерируются:

```bash
npm run sync
```

Каталогов три, а Сред со скиллами пять: `.agents/skills` читают Codex, Cursor и OpenClaw, `.claude/skills` — Claude Code, `.gemini/skills` — Gemini CLI. Свой каталог заводится только там, где Среда чужие не читает; причины — в [docs/environments.md](docs/environments.md#three-skill-directories-not-five).

А вот MCP-конфиг у каждой Среды свой, и схемы у них разные — `mcpServers` против `servers`, `url` против `serverUrl` и `httpUrl`. Файлы перечислены в таблице [Среды](#среды) выше.

Проверки перед PR:

```bash
npm test
```

Линт следит за структурой скиллов и синхронностью копий, `test-skill-rules.mjs` — за тем, что критичные правила не выпали из инструкций при переписывании, `check-mcp-configs.mjs` — за тем, что MCP-конфиги всех шести Сред указывают на одни и те же три адреса, описаны в README и не содержат статических ключей вместо OAuth. Проверки Реестра здесь больше нет: он валидируется на сервере в момент чтения, потому что PR-ревью у таблицы нет.

## Инфраструктура

MCP-сервер Google Ads — форк [googleads/google-ads-mcp](https://github.com/googleads/google-ads-mcp), живёт в отдельном репозитории. Добавлены сбор семантики (`planning_generate_keyword_ideas`) и Реестр (`registry_find_client`, `registry_list_clients`). Официальный сервер собирать семантику не умеет: `KeywordPlanIdeaService` не запрашивается через GAQL.

Разворачивается в Docker на хостинге агентства по адресу `https://google-ads-mcp.qmedia.by/mcp`, рядом нужен Redis — иначе сессии Менеджеров не переживают перезапуск контейнера. Полный список переменных окружения и порядок развёртывания — в `FORK.md` репозитория форка.
