# qmedia-ads-agent

Инструкции и скиллы для AI-агента, работающего с рекламными кампаниями в Google Ads, Яндекс Директе и VK. Агент запускается в Codex или Claude Code; репозиторий он использует только на чтение.

Секретов здесь нет и быть не должно. Никаких `.env`, никаких токенов: авторизация у всех Провайдеров идёт через браузерный OAuth, а developer token и client secret Google Ads живут на сервере агентства.

## Что подключено

| Провайдер | MCP | Доступ |
|---|---|---|
| Google Ads | собственный сервер агентства | только чтение |
| Yandex Direct | `https://lidfly.ru/mcp/v3` | чтение и запись |
| VK | `https://lidfly.ru/mcp/v3` | чтение и запись |

Meta и TikTok — после MVP. У обеих площадок есть официальные MCP-серверы, но Meta пока в open beta с поаккаунтной раскаткой.

## Быстрый старт для Менеджера

1. Клонируйте репозиторий и откройте его в Codex или Claude Code.
2. Убедитесь, что ваш рабочий Google-аккаунт внесён в Test users — без этого OAuth Google Ads не пройдёт. Если не уверены, спросите у того, кто администрирует MCP-сервер.
3. Пройдите OAuth для обоих серверов: `google-ads` и `lidfly`.
4. Проверьте, что всё живо:

```text
Покажи кампании клиента <название> в Google Ads за последние 30 дней.
```

**OAuth Google Ads протухает каждые 7 дней** — это известное свойство, а не поломка (см. [ADR-0007](docs/adr/0007-oauth-app-stays-in-testing.md)). При ошибке авторизации просто пройдите вход заново; агент подскажет это сам через скилл `connection-doctor`.

## Что умеет

```text
Собери семантику для <услуга> по Беларуси, язык русский.
```

```text
Сгруппируй эти запросы по интенту и предложи посадочные страницы.
```

```text
Проверь кампанию «Бренд» в Директе, ничего не меняй.
```

Результаты агент отдаёт файлом — CSV, который вы импортируете в таблицу. Между сессиями он ничего не помнит, поэтому регион и язык называйте явно.

## Клиенты и Аккаунты

Связка Клиента с его рекламными кабинетами лежит в [registry.yaml](registry.yaml). Новый Клиент добавляется туда через PR — агент этот файл не правит.

Реестр направляет агента, но ничего не запрещает на стороне сервера: ограничения по списку Аккаунтов у нас нет, границы задают права в самом Google Ads. Подробнее — в [ADR-0003](docs/adr/0003-google-ads-mcp-access-control.md).

## Разработка

Скиллы правятся **только** в `skills-source/`. Клиентские копии в `.agents/skills` (Codex) и `.claude/skills` (Claude Code) генерируются:

```bash
npm run sync
```

Проверки перед PR:

```bash
npm test
```

Линт следит за структурой скиллов и синхронностью копий, `test-skill-rules.mjs` — за тем, что критичные правила не выпали из инструкций при переписывании, `check-registry.mjs` — за валидностью Реестра.

## Инфраструктура

MCP-сервер Google Ads — форк [googleads/google-ads-mcp](https://github.com/googleads/google-ads-mcp) с одним добавленным инструментом `planning_generate_keyword_ideas`, живёт в отдельном репозитории. Официальный сервер собирать семантику не умеет: `KeywordPlanIdeaService` не запрашивается через GAQL.

Разворачивается в Docker на хостинге агентства по адресу `https://google-ads-mcp.qmedia.by/mcp`, рядом нужен Redis — иначе сессии Менеджеров не переживают перезапуск контейнера. Полный список переменных окружения и порядок развёртывания — в `FORK.md` репозитория форка.
