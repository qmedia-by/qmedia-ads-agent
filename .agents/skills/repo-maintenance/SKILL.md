# Repo Maintenance

Use when the task is to change this repository rather than to run a campaign.
This is the only case in which the repository is writable; every other session
treats it as read-only, and that rule still applies to reports, notes and cache
even here.

Two different agents use this checkout. The campaign agent reads `AGENTS.md`,
`CONTEXT.md` and the task skills. You read `docs/`.

## Read before editing

Start with `docs/README.md` — it maps the rest and states
how these documents are kept. Then the one that owns your change:

| Change | Read |
|---|---|
| a rule the agent must follow | `docs/invariants.md` |
| anything Provider-specific | `docs/providers.md` |
| a new Среда, or a skills or MCP config path | `docs/environments.md` |
| how the pieces connect, or an alternative you are about to propose | `docs/architecture.md` |
| the workflow itself | `docs/changing-this-repo.md` |

The server's own documentation is `FORK.md` in `qmedia-by/google-ads-mcp`. It is
the authority on deployment, environment variables and the Registry parser — do
not restate it in this repository.

## Rules that decide most of the work

- **Decide the layer first.** A fact whose loss gives the Manager a wrong answer
  belongs in a tool's response, not in an instruction. `AGENTS.md` holds only
  what is true every session; Provider detail goes in a skill; maintenance
  guidance goes in `docs/`. The table and the reasoning are in
  `docs/changing-this-repo.md`.
- **Edit `skills-source/` only.** The copies under `.agents/`, `.claude/` and
  `.gemini/` are generated by `npm run sync`.
- **Run `npm test` before you are done.** It checks skill structure, that the
  generated copies match source, that load-bearing sentences survive, and that
  all eight Environment configs agree.
- **Keep `AGENTS.md` short.** Under about a hundred lines; it is paid for in
  every session. `CLAUDE.md` is a symlink to it, never a copy.
- **Nothing private, ever.** Both repositories are public: no tokens, no Client
  names, no account ids, no address of a private resource — including in
  `docs/manager-guide.md`.
- **Update the Manager's documents in the same change** when a Manager has to
  act differently: `docs/manager-setup.md` if the setup changes,
  `docs/manager-guide.md` if the day-to-day does. Both keep their paths and file
  names — department documents link to the guide, and the setup page is the
  public link handed to a new Manager.

## Changes that reach the server

A change spanning both repositories rolls out in a fixed order: merge and deploy
`google-ads-mcp`, verify on a real Client, then merge `qmedia-ads-agent`. The
reverse order ships instructions that reference behaviour which does not exist
yet.

## Output

Say which files changed and which layer each fact landed in, and name anything
you deliberately left out. If a change needs a decision that is the Manager's to
make — dropping an Среда, promising writes where skills do not load, anything
that changes what the Manager's guide promises — put the option in front of them
instead of taking it.
